## 2. Roles (exactly four; no "faculty admin")
- **Student:** login, limited profile edit (phone, address, DOB), see dept/faculty/program/matric no, view available courses for own dept/program/level/semester, register (no duplicates), view registered courses and units, view APPROVED results only, academic history and CGPA, print registration summary and result statement. Cannot touch others' data or grades.
- **Lecturer:** only assigned courses; class list; enter CA and exam scores; save draft; submit for review; see status and feedback; course summaries. Cannot edit submitted results unless reopened; cannot approve own.
- **Dept Admin:** scoped to own department only. Manage students, lecturers, courses, lecturer-to-course assignments, levels/programs; view registrations; approve, reject (feedback required) or return results; reopen; departmental reports. No super admin access.
- **Super Admin:** university-wide. Faculties, departments, programs, sessions and semesters (one current), users (activate/deactivate/suspend, change role), courses and allocations, registrations, result oversight, reports, activity log.

## 3. Business rules to enforce on the BACKEND
1. Student registers only courses for their dept, program, level and semester.
2. No duplicate registration for the same course in the same semester.
3. Lecturer enters results only for assigned courses.
4. Results must be submitted before approval; only that dept's admin approves.
5. Students see only approved results.
6. Every submission, approval, rejection, reopen or modification goes to an audit log.
7. Grading: CA max 30, exam max 70. 70-100 A (5), 60-69 B (4), 50-59 C (3), 45-49 D (2), 40-44 E (1), 0-39 F (0). GPA = sum(grade point x units) / sum(units). Keep it in config and document it.
